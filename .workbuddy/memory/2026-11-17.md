## 手机/平板手势控制台方案（设计文档，未改代码）

- 产出：`/Users/huangyu/魔兽/开源魔兽争霸/手机平板手势控制台方案.md`（776 行，17 节），覆盖现状盘点、五层架构、手势映射表、SD/HD 适配、文件清单、测试验收、P0–P6 分期、风险登记。
- 核心结论：把手势做成项目里**第三个外部输入 Host**（`GestureMatchHost` + `setGestureHost()`），照 `setVoiceHost(makeVoiceHost({...}))`（mapViewer.ts:11107）与 `setGamepadHost()`（:11365）的范式，把 `GestureIntent` 落到 `runCommand` / `orderClickAt` / `moveAt` / `selectAt` / `selectBox` / `minimapClick` / `panTo` / `setZoomStop`。不新增 `Command`、不碰 `Authority.execute`、不碰 flavor 数据线与联机协议。DOM 控件（SD FDF / HD WebUI 菜单）复用 `VirtualCursor` 合成真实 pointer 事件。
- SD/HD 关键实证：`specs/reforged-hud/spec.md` 已证两版 HUD 控件几何完全相同（CONSOLE_ZONES、4×3 命令卡、69px 英雄栏），`mapViewer.ts:12254/12267` 无 flavor 分支 → 手势识别/动作层 0 分支；唯一要读 `hdArt()` 的是 `consoleUi.ts:99-101` 的 `CONSOLE_ART_TOP`（de=0.1383，其余 0.1317）。差异集中在菜单层（fdf*.ts vs ui/hd/*）与 Options 层（SD FDF 三页 vs HD 五页），共用 `OPTION_DEFS`。
- 前置阻塞（P0 go/no-go）：`android/.../MainActivity.java:17-20` 自述 Android WebView 无 File System Access API，拿不到 WC3 安装目录 → **游戏根本进不去**；且 APK 无原生 JS 桥、无 PWA。方案推荐 SAF + `shouldInterceptRequest` 虚拟协议，保持「零暴雪资产进包」口径。
- 已知冲突点：`main.ts:2092/2096` 当前主动 `preventDefault` 掉 `gesture*` 与多指 `touchmove`，必须改成仲裁式 `gestureClaims()`；`ui/inputSource.ts:16/18/40/80` 需加 `"gesture"` 来源，否则合成事件被误判成 `"gamepad"`。`#ui` 的 transform（body.in-game）与 `--hud-scale` 会让手算坐标错位 → 只用 `getBoundingClientRect()` 缓存实测矩形。
- 性能口径：弱机 11.6–37.7fps / 26–86ms 帧（docs/perf-research.md），手势层要求零常态帧开销、每帧 0 次 layout read；触屏默认降档（手机 450p/576p + Low Performance Mode）。
